# Deployment

The project builds with Maven on 64-bit Java 17 or newer. JOGL and GlueGen 2.6.0 are resolved from the JogAmp Maven repository configured in `pom.xml`; their `*-main` dependencies include Windows AMD64 native libraries. Packaging requires a JDK with `jlink` and `jpackage` available on `PATH`.

Build and test:

```powershell
mvn test
mvn package
```

Launch from source with:

```powershell
.\run.ps1
```

Build the click-to-run app image and portable ZIP:

```powershell
.\scripts\package-windows.ps1
```

The script produces `dist\Gargantua\Gargantua.exe` with a bundled Java runtime and JOGL dependencies, plus `dist\Gargantua-0.1.0-windows-x64.zip`. Double-click the EXE to launch. When moving the app image, preserve its full folder structure; the executable depends on neighboring `app` and `runtime` directories. This is a Windows x64 distribution, not an installer.

The script packages the project, resolves the Maven runtime classpath, then starts the desktop application in a separate JVM. On Java 24+, it enables native access for JOGL. For the automated context, first-frame, and spin-control check, use `.\run.ps1 -GraphicsSmokeTest`.

On startup, read the diagnostic output and confirm the actual renderer is the intended NVIDIA adapter. Configure the exact `java.exe` on PATH as High performance in Windows Graphics settings as described in [README.md](README.md).

No MSI installer, signed Windows distribution, or clean-machine Windows 11 acceptance test has been produced. Build artifacts in `dist` are regenerated by the packaging script.
